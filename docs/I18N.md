# Internationalisation (i18n)

The portfolio supports **Spanish** and **English**. There is no locale routing; language is controlled via a toggle in the navbar.

## Files

| File | Role |
| ---- | ---- |
| `src/lib/i18n/types.ts` | `Translations` interface (key contract) |
| `src/lib/i18n/es.ts` | Spanish translations |
| `src/lib/i18n/en.ts` | English translations |
| `src/lib/i18n/LanguageContext.tsx` | Provider + `useLanguage()` hook |
| `src/lib/i18n/localeUtils.ts` | Spanish region detection and storage keys |

## Usage in components

```tsx
'use client';
import { useLanguage } from '@/lib/i18n/LanguageContext';

export default function Example() {
    const { t, language, setLanguage, toggleLanguage } = useLanguage();
    return <p>{t.hero.bio}</p>;
}
```

- `setLanguage('es' | 'en')` — explicit change with persistence
- `toggleLanguage()` — alternates between ES and EN

## Adding a new key

1. Add the key in `types.ts` under the relevant section (`nav`, `hero`, `common`, etc.).
2. Translate in **both** `es.ts` and `en.ts`.
3. Use `t.section.key` in the component — never hardcode user-facing text.

## Bilingual content in data

Projects use `Record<Language, string>` for descriptions:

```ts
description: {
    es: 'Texto en español',
    en: 'Text in English',
},
```

Access: `project.description[language]`.

## Persistence and first visit

| Key | Values | Use |
| --- | ------ | --- |
| `portfolio-lang` | `es` \| `en` | User-selected language |
| `portfolio-lang-prompt-dismissed` | `true` | Suggestion banner already dismissed |

**First visit (no `portfolio-lang`):** the site loads in **English** by default.

The script in `layout.tsx` syncs `document.documentElement.lang` before the first paint if a preference is stored.

## Spanish suggestion banner

Component: `LanguagePrompt` — fixed bottom banner, non-blocking.

Shown only if:

1. `portfolio-lang` does not exist in `localStorage`
2. `portfolio-lang-prompt-dismissed` does not exist
3. `detectSpanishRegion()` returns `true`

### Detection signals (`localeUtils.ts`)

| Signal | Example |
| ------ | ------- |
| Browser language | `navigator.languages` starts with `es` |
| ISO region | `es-CO`, `es-MX`, `es-ES`, etc. |
| Time zone | `America/Bogota`, `America/Mexico_City`, `Europe/Madrid`, … |

No geolocation or external APIs.

### Banner actions

- **Accept** → `setLanguage('es')` + dismiss
- **Dismiss** / **Escape** → keeps English + dismiss
- Bilingual copy (ES + EN) because the site starts in English

i18n keys: `common.language_prompt_*`

## Rules

- All visible user text must go through i18n.
- Aria-labels and error messages too.
- Proper nouns (SkyVault, SelanFlow, GitHub) are not translated.
- Maintain ES/EN parity: if you add a key in one language, add it in the other.
- Do not revert the `'en'` default on first visit; the banner covers the suggestion for Spanish-speaking regions.
